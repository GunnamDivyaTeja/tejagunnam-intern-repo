# AI Usage Guidelines

## Research and Learn

### AI tools typically used for my role (ML Engineer)

- Coding assistants like GitHub Copilot, Claude Code and Cursor
- Chat assistants like ChatGPT, Claude and Gemini for explaining concepts, debugging and writing docs
- Model APIs like the OpenAI API (which Focus Bear uses) and Hugging Face for building features
- Notebook assistants like the one in Google Colab

### Benefits and risks of using AI at work

Benefits:

- Coding, debugging and writing boilerplate is faster
- I can get a quick explanation of code, libraries or papers that are new to me
- It helps with writing documentation and test cases
- It can suggest approaches that I did not think of

Risks:

- Confidential data or code can get leaked if I paste it into a public tool
- The answers can be wrong or made up, even when they sound confident
- The code can have bugs or security problems
- Generated code can have licence or copyright issues
- My own skills can get weaker if I stop thinking for myself

### Information that should never be entered into AI tools

- User data like emails, habits, health details or survey answers
- Passwords, API keys and tokens
- Private company code, unless the tool is approved by the company
- Internal plans, finances and unreleased features
- Personal details of team members

### How to fact-check AI-generated content

- Run and test the code myself before using it
- Check the claims against the official docs or the original source
- Make sure the libraries, functions and references it mentions actually exist
- Read every line before I use it
- Ask a teammate to review it if it is important

## Reflection

### When to use AI and when to rely on my own skills

I will use AI for things like boilerplate code, explaining errors, understanding a new library, and improving the wording of my docs. These are tasks where it saves time and I can easily check the result.

I will rely on my own skills for designing the solution, making decisions about the model or data, reviewing code, and anything that involves user data. I also want to do the task myself first when I am learning something new, because otherwise I will not really understand it.

### Avoiding over-reliance on AI

- Try the problem myself first, and use AI only when I am stuck
- Never use code that I cannot explain line by line
- Ask AI to explain why, not just give the answer
- Sometimes solve tasks without AI to keep my skills sharp
- Treat the output as a suggestion, not the final answer

### Steps to ensure data privacy when using AI tools

- Only use tools that are approved by Focus Bear for company work
- Never paste user data, secrets or keys into any AI tool
- Remove or replace names, emails and other identifiers before sharing an example
- Use small made-up examples instead of real data when asking for help
- Ask my team lead if I am not sure whether something is okay to share

## Task

### A task I improved using an AI tool

I used an AI assistant to help me draft my internship time plan and to format my reflection notes into markdown.

### Did the output need editing or fact-checking?

Yes. The first draft of the time plan had blank dates and guessed locations that I had to fix myself. The writing style also did not sound like me, so I rewrote parts of it in my own words. For the reflections, I wrote the answers myself and only used AI to clean up the formatting, and I read the full file before committing it.

While setting up this repo, I also found that the setup README had a mistake in the `.env` format. This showed me that I should always check instructions and outputs against how the code actually works, and not just trust them.

### One best practice I will follow

I will never use AI-generated code or text that I do not fully understand. I will read it, test it and check it against the official docs before I commit it.
